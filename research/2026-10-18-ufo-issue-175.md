# UFO issue 175: "Thinking about a variable-first version of UFO"

Opened 2021-03-26 by Jany Belluz (belluzj). Last comment 2021-04-09.
Still open. Fourteen comments, four people: Belluz, Just van Rossum,
Chris Simpkins, Erik van Blokland.

## The proposal

1. One designspace plus one UFO with layers as sources, instead of one
   designspace plus N UFOs. Cuts duplicated fontinfo and unicodes.
2. Variation inside kerning.plist and features.fea: "each number can
   specify its own variation space" instead of duplicating the whole
   file per master.
3. Adopt Designspace 5 so one designspace always describes a family.
4. A UFO may contain a designspace the way it contains features.fea.
   UFO becomes the top-level container for a family.
5. Once tools accept this, UFO can evolve internally.

All opt-in. A single number is a constant variation space.

## Ideas in the thread worth keeping

- Just: kerning as CSV, left column, right column, then N columns for
  N sources. This is exactly Fontra's `kerning.csv` today.
- Belluz: a layer's meaning (which master, background-of, color) must
  be structured data in the layer, not encoded in its name. Names are
  derived from the data by an algorithm, with truncation and
  uniqueness handled there. Same split as Glyphs IDs vs names.
- Belluz: glyph-has-layers versus layer-has-glyphs. UFO is the
  latter. Glyphs and Fontra are the former. Converting between them
  creates many one-glyph layers (Glyphs backup layers).
- Van Blokland: one source can appear at several designspace
  locations, and one UFO can belong to several designspaces. So the
  location must not live in the layer or the file name.
- Belluz: bracket layers hit limits as soon as conditions need AND or
  OR. Conditions belong in structured rules, not layer names.

## Why it died

No maintainer decision was ever requested or given. The thread drifted
into layer naming conventions and whether locations belong in paths.
Nobody wrote a proposal document or a prototype. Designspace 5 shipped
separately in fontTools, which removed the urgency for item 3, and the
rest stayed as ideas.

## What this means for lilufo

Every structural idea here is five years old, uncontroversial among
the people who wrote UFO, and still unimplemented in UFO. The blocker
was not disagreement but the absence of anyone to write and ship it.
A new format can take all five points as settled requirements.

Open question the thread raised and did not answer: glyph-has-layers
or layer-has-glyphs as the on-disk truth. Fontra and Glyphs chose
glyph-has-layers. The proposal's per-glyph file does the same.
